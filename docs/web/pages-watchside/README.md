# `watchside/` on the existing Pages site — ready to copy

The two files beside this one are the **exact bytes** to publish into
`Anoteros-Labs/anoteros-labs.github.io` under `watchside/`:

```
index.html          ->  watchside/index.html          (/watchside/ is a 404 today)
support/index.html  ->  watchside/support/index.html  (replaces the current thin page)
```

They are generated by `npm run build:site:pages`, and
`tests/extension/pagesArtifact.test.ts` asserts these checked-in copies still
match that build — so they cannot quietly drift from the source they came from.

## Why these are checked in rather than only built

`dist-pages/` is gitignored, so a build output is not reviewable and not
copyable without running a build first. This directory follows the convention
`docs/web/invite-landing/` already set: the publishable file lives in the
repository, so publishing is a copy and nothing else.

## What is deliberately NOT here

**`privacy/`.** A privacy page is already live at `/watchside/privacy/`,
generated from the same `docs/PRIVACY.md`. Overwriting a live policy page as a
side effect of publishing a support page is not a trade worth making, so the
build's copy is left in `dist-pages/` and the live one is left alone.

**`CNAME`, `404.html`, `/i/`.** A `CNAME` here would rebind the entire org site
to `watchside.app` and take `/kickback/` with it. The other two only work from a
domain root — Pages serves `404.html` from the root of a site, not from a
subdirectory. All three absences are asserted by `publicRouting.test.ts`.

## Why `index.html` is included and not optional

`/watchside/` returns 404 today, and both the support page's back link and its
footer point there. Publishing support alone would ship a page whose own
navigation is broken. The two files go together.

## What this replaces

The support page currently live at `/watchside/support/` covers two things:
feedback from inside Watchside, and an email address. It does not cover the case
the page exists for — **the panel not appearing at all** — nor sign-in trouble,
stale builds, notification delivery, or account deletion. The copy here covers
all six.

## After publishing

```
curl -sI https://anoteros-labs.github.io/watchside/           # 200
curl -sI https://anoteros-labs.github.io/watchside/support/   # 200
```

The account panel's Support link points at the second of those. It is already in
a shipped build, so this is a fix to something users can reach today — not
preparation for something later.
