# M3D — Creator discovery measurement

*Operational contract. The full history, evidence and reasoning live in
`docs/reports/g6-m3d-creator-discovery-2026-08-30.md`; this is what you need to
run and trust the thing.*

---

## What M3D measures

**One fact, at one moment:** when somebody performs a socially initiated
Watchside JOIN, did they *already* follow that creator on Twitch?

That is a **baseline**, not an outcome.

## What M3D does not measure

It does **not** show that Watchside:

- caused a follow, or that the viewer followed afterwards
- converted anybody into a follower
- produced incremental viewing, retention, subscriptions, Bits or revenue

It also does not read anybody's follow list. It asks about **one creator** — the
one just joined — and nothing else. There is no backfill: a JOIN that could not
be measured at the time never gets an answer later.

---

## Populations

Say which one you mean. "Eligible" never means "has an observation".

| | Definition | View |
| --- | --- | --- |
| **A** socially initiated JOINs | `join_clicked` that navigated, minted an attribution, `social_count > 0`, non-internal actor | `m3d_social_joins_v` |
| **B** measurement-eligible | an A whose `join_measurement_status` is `attempted` — the client's JOIN-time decision | `m3d_measurement_v` |
| **C** retained baselines | an observation with `relationship_present` **not null**, bound to an A by actor **and** attribution, still retained | `m3d_observations_v` |
| **D** unobserved eligible | B − C | derived in `m3d_coverage_v` |

**B is the decision, not the outcome.** Defining it by the existence of an
observation would make coverage tautologically 100%.

## Metrics

### Coverage — `m3d_coverage_v`

```
coverage_rate = observed_baselines / measurement_eligible
```

`NULL` when the denominator is zero — never `0`. "We measured none of them" and
"there was nothing to measure" must not look alike.

Numerator and denominator describe the **same** JOINs. `observed_outside_eligible`
counts baselines belonging to JOINs never judged measurable; today that is
pre-instrumentation history, and a non-zero value later means the populations
have drifted.

**The denominator is client-reported.** It is Watchside's own decision at the
JOIN, not a server fact. Say so whenever you quote it.

### Relationship — `m3d_relationship_v`

```
not_followed_share = count(relationship_present = false) / count(relationship_present is not null)
```

Over **currently retained** observations only. Never all JOINs, never all
eligible JOINs, never all users.

### Missingness — `m3d_missingness_v`

Eligible JOINs split into measured and unmeasured, on dimensions that already
existed (environment, source surface, mean social count, time span). It shows
whether the two buckets resemble each other. It does not establish that they do.

## Four states, deliberately separate

| State | Means | Depends on |
| --- | --- | --- |
| **COLLECTION OPERATIONAL** | the pipeline works end to end | the code — **this is what M3D closing required** |
| **COVERAGE OBSERVABLE** | enough post-instrumentation JOINs for a rate to mean anything | production usage |
| **REPORTABLE** | privacy gates pass, an aggregate may be looked at | production usage |
| **INTERPRETABLE** | we know whether the aggregate represents anything | somebody doing the analysis |

`src/core/m3dReadiness.ts` judges a snapshot and returns the state, the
blockers, and whether the share may be published. It **fails closed**.

**Current status: COLLECTION OPERATIONAL.** Everything beyond it waits on real
usage.

## Before quoting the number externally

All of these, via `assessReadiness()`:

- at least **30** eligible JOINs (coverage means something)
- at least **10** retained baselines across at least **3** actors
- the view itself reports `reportable = true`
- `observed_outside_eligible` is zero
- **the measured-versus-unmeasured comparison has been run and reviewed** — this
  one is an input, because no query can tell whether a human thought about it

**Thresholds are PROVISIONAL.** They are floors below which a number is
obviously noise. They are not statistical significance and must not be described
as such.

### The only permitted wording

> *X% of socially initiated Watchside JOINs with a currently retained
> follow-baseline observation went to creators the viewer did not already
> follow.*

Generated by `permittedClaim()` so it cannot drift from the denominator.

### Forbidden

Anything using *caused*, *converted*, *conversion*, *incremental*, *lift*,
*new followers*, *revenue*, *subscription* or *retention*. Also: quoting the
share against all social JOINs, or presenting beta observations as evidence of
discovery lift.

## Missingness — not random, and not to be assumed so

At least one source is **systematic**: users whose authorization predates
`user:read:follows` cannot be measured at all, so the unmeasurable cohort is
systematically *older* than the measurable one.

Visible: `skipped_not_ready`, `skipped_unacknowledged`, `status_missing`, and
B − C in aggregate.

Invisible inside B − C: worker eviction, network failure, Twitch API failure,
credential refresh failure, broadcaster lookup failure, window expiry from clock
skew, and observations deleted later by the Twitch lifecycle. They all present
identically as "eligible, no baseline".

---

## Deletion lifecycle

| Event | Credential | Observations | Watchside analytics |
| --- | --- | --- | --- |
| Twitch deauthorization | deleted | deleted | **preserved** |
| Confirmed `user:read:follows` removal | **kept** | deleted | **preserved** |
| Account deletion | deleted first | deleted | deleted |
| Sign-out | kept | kept | kept |
| Any transient failure | untouched | untouched | untouched |

**Confirmed scope removal** means one thing only: a **successful** Twitch
refresh whose scope list no longer contains the permission. A timeout, 5xx,
malformed body or ambiguous 401/403 is structurally unable to reach the
deletion.

**Metrics recompute after deletion, so historical percentages move.** That is
correct — the alternative is reporting a relationship we are no longer allowed
to hold. The surviving `join_measurement_status` says only that Watchside
*asked*; it never held an answer and cannot rebuild one.

## Internal actors

Excluded from every reportable surface via `analytics_reportable_events_v`.
They can exercise the real pipeline — the automated acceptance does — without
their data becoming evidence about users, and they **cannot** pad a small real
cohort past the suppression threshold.

---

## Running the automated acceptance

```
WATCHSIDE_ADMIN_TOKEN=<owner diagnostic token> npm run verify:m3d
```

Two seeded Firefox profiles, two real accounts, one real JOIN, one real Twitch
lookup, **no human**. It checks preconditions — identity, friendship, credential,
scope, readiness, baseline — and **refuses with exit code 3 before spending a
JOIN** if any fail.

Never perform a manual JOIN to work around a failure. If it stops, it names what
is missing.

**Seed maintenance** (the one human step, once per profile per session
lifetime): sign in inside the seed profile itself with
`--keep-profile-changes`. This is the sanctioned exception to "the harness never
opens a seed" — see the F5 report §28.10 for the exact command.

## Inspecting production

Owner-gated, shape and counts only, never a follow result:

```
POST /functions/v1/twitch-credential   { "action": "..." }
  acceptance_preconditions   can this actor be measured
  credential_shape           custody, scopes, readiness
  observation_shape          baselines and recent JOINs
  coverage_shape             the coverage and relationship views
  relationship_probe         walks the Twitch path read-only
```

`observation_shape` returns `answered` — whether a real answer was recorded —
and **never which answer**.

## What requires revalidation

Re-run the full M3D gates if any of these change:

- JOIN semantics, social eligibility, or the attribution model
- the analytics acknowledgement path (`flush` / queue behaviour)
- credential custody, Twitch OAuth scopes, or the Twitch follow API
- the observation schema or any deletion semantics
- the small-cohort threshold or the internal-actor definition
- experiment assignment semantics
- browser architecture affecting background-worker lifetime

Cosmetic and unrelated changes do not.

---

## What M3D enables next, and what it does not

**Enables:** a creator-discovery baseline; segmentation by experiment arm,
cohort and source where those already exist; comparison against dwell, arrival
and shared-watch; a foundation for later causal work.

**Still future:** follow conversion after a JOIN, economic attribution, causal
lift, population representativeness, and statistical confidence at scale.

**M3E-a (subscriptions) remains HOLD.** No subscription or emote scope exists,
and tests assert their absence.
