## 1. Version locations changed

The repository already had a canonical single-source arrangement, and it was
**preserved rather than replaced**:

- `public/manifest.json` is the **source of truth**.
- All four build configs read it into `__KICKBACK_VERSION__`:
  `vite.config.ts:15`, `vite.background.config.ts:15`,
  `vite.testlab.config.ts:29`, `vitest.config.ts:31` — each as
  `JSON.parse(readFileSync('public/manifest.json', 'utf8')).version`.
- `package.json` must agree with it; `npm run verify:store` and
  `tests/extension/releaseVersion.test.tsx` both enforce that agreement.
- The UI reads the constant and never a literal.

`package-lock.json` line 3 is the root package version and line 9 is

  not require editing the test that guards releases. It passed unchanged.

## 11. Loading this build for owner smoke

**This is a fresh install path, not an update to the Store version.** Chrome
will not replace the Store-installed 0.4.1 with this — they are different
installs of the same extension ID, so **disable or remove the Store one first**
or Chrome will refuse the load with an ID conflict.

### First time

1. **Disable the Store-installed Kickback.** `chrome://extensions` → find
   Kickback → toggle it **off** (or Remove). Both installs share the ID
   `ngfopkeokddfnncdhfkhnffilbdhkkip`, and Chrome allows only one.
2. **Extract** `releases/Kickback-Private-Beta-v0.5.0.zip` somewhere permanent —
   Documents or Desktop, **not** Downloads. You get a `Kickback` folder.
3. `chrome://extensions` → turn on **Developer mode** (top right).
4. **Load unpacked** → select the extracted **`Kickback`** folder (the one
   holding `manifest.json` and `README-TESTERS.txt`).
5. Open Twitch and refresh any already-open Twitch tabs, so the content scripts
   reconnect to the new worker.
6. Sign in with **Continue with Twitch** if prompted.

### Confirm you are actually on 0.5.0 before testing anything

Two places, and they must agree:

- `chrome://extensions` shows **0.5.0** under Kickback.
- Click your avatar in the Kickback panel — the account card reads
  **`Kickback v0.5.0`**. (The panel footer also shows `v0.5.0`.)

If either says 0.4.1, you are on the Store build and the multi-destination fix
is not present.

### Re-loading after a later rebuild

1. Extract the new ZIP.
2. Copy its files **into the same folder** you installed from, replacing the old
   ones. Keeping the same path matters — Chrome treats a new location as a new
   install, which means signing in again.
3. `chrome://extensions` → click the **reload arrow** on Kickback.
4. **Refresh every Twitch tab.** The service worker restarts, but content
   scripts do not reattach on their own.

### Afterwards

To go back to the Store build: remove the unpacked one, then re-enable the Store
install. Both accounts stay signed in on the hosted backend; only local state is
per-install.

### What to run

The first-stage multi-destination retest — twelve steps — is in
[`0.5.0-multi-destination-smoke-failure-2026-08-28.md`](0.5.0-multi-destination-smoke-failure-2026-08-28.md) §19,
with the read-only diagnostic SQL in §16 if the UI and the database appear to
disagree.

**Both accounts must be on 0.5.0 to see the whole behaviour.** Account A is the
one publishing multiple destinations, and Account B must be a build that reads
`list_friend_destinations` — a 0.4.1 Store client will only ever show A at their
primary channel, correctly, and that is not a bug.
